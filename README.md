# 기업건강검진 — 코스닥 상장사 재무위험 진단

한국은행과 전자공시(DART)에 공개된 데이터로 코스닥 상장회사의 재무 상태를 분석해서,
**그 회사만의 문제로 인한 부실 위험**을 0~100점으로 보여주는 개인 프로젝트입니다. 실제로
상장폐지됐던 회사들의 과거 재무 데이터로 학습한 모델을 사용합니다.

여기서 "그 회사만의 문제"라는 말이 중요한데요 — 예를 들어 기준금리가 올라서 모든 회사
사정이 같이 어려워진 것과, 그 회사 하나만 유독 안 좋아진 것은 다른 문제입니다. 이 프로젝트는
경기 전체에 공통으로 영향을 주는 부분은 최대한 걷어내고, "그 회사만" 유독 위험한 부분만
점수에 반영하려고 합니다.

> ⚠️ **면책조항**: 이 사이트는 개인 포트폴리오/학습 목적으로 만든 데모입니다. 표시되는
> 위험점수는 표본이 매우 적은 실험적 모델의 결과이며, 통계적으로 충분히 검증되지 않았습니다.
> **실제 투자 판단, 신용평가, 거래 의사결정에 사용해서는 안 되며**, 특정 기업의 재무 건전성을
> 공식적으로 나타내지 않습니다. 표시된 기업명은 모델 검증을 위한 예시일 뿐입니다.

## 무엇을 보여주나

- 회사별 위험점수(0~100)와 "왜 이 점수가 나왔는지"에 대한 지표별 설명
- 주요 재무지표 9종이 최근 몇 년간 어떻게 변해왔는지
- 비슷한 업종의 다른 회사들과 비교했을 때의 위치
- 완전자본잠식처럼 누가 봐도 위험한 상황은 규칙으로 강제로 높은 점수를 매김

## 어떻게 만들었나

```
DART(재무제표) ──┐
                  ├─▶ 데이터 수집 ──▶ 재무비율 계산
한국은행(금리) ──┘                          │
                                             ▼
                                상장폐지 이력으로 정답(라벨) 표시
                                             │
                                             ▼
                      경기 영향 제거 (기준은 항상 과거 데이터로만 잡음)
                                             │
                                             ▼
                            추세·회사 규모 정보 추가
                                             │
                                             ▼
                          모델 학습 + 판단 기준선 정하기
                                             │
                                             ▼
                        위험점수 계산 + 자본잠식 등 예외 규칙 적용
                                             │
                    ┌────────────────────────┴────────────────────────┐
                    ▼                                                   ▼
              React 웹앱(풀스택 데모)                          Streamlit 데모(원클릭 배포)
```

두 화면(React / Streamlit) 모두 미리 계산해 둔 결과 파일(`backend/data/processed/`)을
읽기만 하므로, 배포된 데모를 그냥 구경하는 데는 API 키가 필요 없습니다. 데이터를 새로
받아오거나 모델을 다시 학습시킬 때만 키가 필요합니다.

## 위험점수는 어떻게 계산되나

**1. 데이터를 모은다.** DART에서 재무제표(2015~2025년), 한국은행에서 기준금리, KRX에서
코스닥 상장폐지 이력을 가져옵니다. 코스닥 회사가 중심이지만, 자본잠식·감사의견거절처럼
어느 시장이든 똑같은 기준으로 판단되는 코스피 상장폐지 사례 일부도 학습 데이터를 조금이라도
늘리기 위해 같이 넣었습니다.

**2. 재무지표를 계산한다.** ROA(수익성), 부채비율, 유동비율 등 대표 지표 9개를 계산합니다.
회사 자본이 마이너스인 완전자본잠식 상태에서는 일부 지표가 오히려 좋아 보이게 계산되는
함정이 있어서, 이런 경우는 따로 표시해 둡니다. 또한 최근 한 해 성적만 보지 않고 "작년보다
나빠지고 있는지"(추세)와 회사 규모도 같이 봅니다 — 상장폐지는 한순간의 수치보다 악화되는
속도가 더 중요한 신호인 경우가 많기 때문입니다.

**3. 경기 영향을 걷어낸다.** 금리가 오르면 다들 같이 힘들어지는 것처럼, 모든 회사에 공통으로
영향을 주는 부분은 떼어내고 "그 회사만의" 위험만 남깁니다. 이때 중요한 원칙 하나: 이 기준은
반드시 학습에 쓸 과거 데이터로만 잡고, 검증에 쓸 최근 데이터는 절대 미리 들여다보지
않습니다 — 안 그러면 시험문제를 미리 보고 푸는 것과 다를 게 없어지기 때문입니다.

**4. 정답(라벨)을 만든다.** 실제로 상장폐지된 회사의, 폐지되기 1년 전 재무제표에 "위험"
표시를 합니다. 다만 가장 최근 1~2년치 데이터는 아직 상장폐지 여부가 확정되지 않았을 수
있어서(지금은 멀쩡해 보여도 올해 안에 폐지될 수도 있으니) 학습·검증에는 쓰지 않고 예측에만
사용합니다.

**5. 모델을 학습시킨다.** 로지스틱 회귀라는, 비교적 단순하고 "어떤 지표가 점수를 얼마나
올렸는지" 그대로 설명할 수 있는 통계 모델을 씁니다. 부실기업 사례가 전체의 2% 정도로 워낙
적어서 이 비율을 인위적으로 보정해 학습하는데, 그 때문에 "위험할 확률 50%"라는 기준이 실제
확률과는 다릅니다. 그래서 별도로 이 데이터에 가장 적절한 판단 기준선(분류 임계값)을 찾아 같이
보여줍니다 — 검증구간 라벨은 보지 않고, 학습구간 내부 교차검증만으로 재현율을 더 중시하는
F2 기준으로 고릅니다.

## Altman Z-Score와 비교

전통적으로 감사·신용평가 실무에서 널리 쓰이는 Altman Z-Score(1968, 이 프로젝트는 장부가
기준 변형인 Z'-Score 사용)와 우리 모델의 판별력을 같은 검증 구간에서 비교해 보여줍니다.

- **제조업 기업만 계산합니다.** Altman Z-Score는 원래 제조업 상장사 데이터로 만들어진
  공식이라, 재고자산·설비자산 비중이 크게 다른 금융업·서비스업 등에 그대로 적용하면 점수가
  왜곡될 수 있습니다. 그래서 한국표준산업분류(KSIC) 제조업 코드(10~34)에 해당하는 기업에만
  Z-Score를 계산하고, 그 외 업종은 이 항목을 표시하지 않습니다.
- **0~100 환산은 별도의 보정 모델로 합니다.** Z-Score 자체는 임의 스케일의 점수라 우리 모델의
  위험점수와 바로 비교할 수 없습니다. 그래서 Z-Score 하나만 입력으로 쓰는 1변수 로지스틱회귀를
  전체 기간 데이터로 학습해(Platt scaling과 같은 방식), "이 Z-Score를 가진 기업이 내년
  상장폐지될 확률"로 다시 계산합니다. 이 확률에 100을 곱한 값이 환산 위험점수입니다.

## 알려진 한계

- **표본이 매우 적습니다.** 검증에 쓴 실제 상장폐지 사례가 25건뿐이라, 결과가 표본을 어떻게
  뽑느냐에 따라 크게 흔들릴 수 있습니다(성능 지표의 95% 신뢰구간이 0.73~0.90으로 넓습니다).
  이 정도 표본에서는 소수점 단위의 작은 변화를 "좋아졌다/나빠졌다"로 해석하면 안 됩니다.
- **지금 보여주는 검증 성능이 실제 서비스 모델과 완전히 같지는 않습니다.** 서비스에 쓰이는
  모델은 검증에 썼던 최신 데이터까지 포함해서 한 번 더 학습하기 때문입니다.
- **일부 지표는 이론과 반대 방향으로 학습됐습니다**(예: ROA). 다른 지표들과의 상관관계
  때문인지 확인해봤지만 원인이 아니었고, 표본 자체가 작아서 생기는 특성으로 보입니다.
- **경기 변수로 기준금리 하나만 씁니다.** GDP 성장률 등을 추가하면 더 정교해질 수 있습니다.
- **상장폐지 사유가 다양한데 전부 같은 "위험"으로 처리합니다.** 자본잠식처럼 재무제표로
  설명되는 사유와, 공시 미제출처럼 재무비율과 관련 없는 사유를 나눠보려 했지만, 그러면
  안 그래도 적은 표본이 3분의 1 이하로 더 줄어들어 오히려 신뢰할 수 없는 결과가 나와
  포기했습니다.
- **일부 회사는 데이터에서 빠져 있습니다.** 719개사 중 52개사는 사명 변경 등으로 DART에서
  재무자료를 찾지 못했습니다. 다른 회사 데이터가 잘못 섞여 들어가는 것을 막기 위해, 이름이
  애매하게 비슷한 정도로는 매칭하지 않고 확실한 경우만 인정하도록 만들었습니다.

## 로컬 실행

```bash
cd backend
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements-dev.txt   # 전체 개발(수집+API+모델 재학습)
# 또는
./.venv/Scripts/python.exe -m pip install -r requirements.txt       # Streamlit 데모만 볼 때

cp .env.example .env   # DART_API_KEY, ECOS_API_KEY 입력 (재수집/재학습 시에만 필요)

./.venv/Scripts/python.exe scripts/build_universe.py   # 대상 기업 목록을 새로 만듦
                                                         # (주의: 이미 만들어 둔 delisted_companies.csv가
                                                         # 있다면 다시 실행하지 마세요 — 코스피 추가분과
                                                         # 종목코드 보정 내용이 사라집니다)
./.venv/Scripts/python.exe scripts/run_pipeline.py      # 수집 → 지표 → 모델 → 위험점수

./.venv/Scripts/python.exe -m streamlit run streamlit_app.py   # Streamlit 데모
./.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000 # FastAPI 서버 (React용)
```

```bash
cd frontend
npm install
npm run dev   # React 프론트엔드 (FastAPI가 떠 있어야 함)
```
